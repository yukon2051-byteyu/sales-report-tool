# 売上データ集計ツール

店舗ごとに届く売上ファイル（CSV・Excel）をまとめて読み込み、**店舗別・カテゴリ別・月別・週別**に集計して Excel レポートを自動で作成する Python ツールです。

> 掲載しているデータ（店舗名・商品名・金額など）はすべて架空のものです。

---

## 解決したい業務課題

複数店舗をもつ小売業で、毎月・毎週行う売上集計の業務を想定しています。

| | 手作業の場合 | このツールを使う場合 |
|---|---|---|
| 作業内容 | 各店舗のファイルを開き、1つのシートにコピー＆ペーストしてから、ピボットテーブルで集計する | ファイルをフォルダに置いて、`集計実行.bat` をダブルクリックする |
| 所要時間（実測） | 約40分（10月分・3ファイル。店舗別の集計のみ） | 約3秒（6か月分・18ファイル。すべての集計と Excel レポートの作成まで） |
| ミス | 貼り付け漏れ・二重貼り付け・計算式の崩れが起こりうる | 同じ手順で毎回処理するので、転記ミスが起きない |
| 入力ミスの発見 | 気づきにくい | 空欄・マイナス値・金額の不一致を、ファイル名と行番号つきで警告する |

※ 所要時間は、2026年10月に開発者本人がサンプルデータで1回だけ測った値です。
手作業は、Excel で3ファイルを開いて1つのシートにコピー＆ペーストし、ピボットテーブルで店舗別の売上合計を作り終えるまで。ツールは、`集計実行.bat` をダブルクリックしてから `output/` フォルダが開くまでを測りました。

## 主な機能

- **複数ファイルの一括読み込み**：フォルダ内の `.csv` と `.xlsx` をまとめて読み込み、1つの表に結合する
- **4つの切り口で集計**：店舗別・カテゴリ別・月別・週別（月曜始まり）に、売上合計と数量合計を計算する
- **Excel レポートの出力**：集計結果を5つのシート（店舗別／カテゴリ別／月別／週別／全データ）に分けて保存する。見出しの装飾・3桁区切り・見出し行の固定で見やすく整え、ファイル名にはデータの期間を入れる（例：`売上集計_2026-05_2026-10.xlsx`）。集計シートには売上合計の棒グラフも入れる
- **今週の売上の特徴**：いちばん新しい週の売上を前週と比べ、3つの文にまとめて画面に表示する（詳しくは「今週の売上の特徴（コメント）」）
- **入力データのチェック**：入力ミスが疑われる行を警告する
- **分かりやすいエラーメッセージ**：よくある失敗の原因と対処方法を日本語で表示する
- **3つの使い方**：ダブルクリックで実行する方法、コマンドで実行する方法、ブラウザの画面（Streamlit）で操作する方法を用意。画面ではファイルのアップロード、集計表とグラフの表示、Excel レポートのダウンロードができる

## 使い方（ダブルクリックで実行する場合）

いちばん簡単な方法です。先に「インストール」の手順を済ませておいてください。

## 使い方（画面で操作する場合）

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

ブラウザで画面（http://localhost:8501）が開きます。

1. 「ファイルをアップロード」を選び、売上ファイルを選択します（複数選択できます）。お試しの場合は「サンプルデータで試す」を選びます。

4. 「Excel レポートをダウンロード」ボタンで、グラフ付きの集計レポートを保存できます。

## 今週の売上の特徴（コメント）

画面版では、集計結果の上に「今週の売上の特徴」を3つの文で表示します。サンプルデータでは次のようになります。

> 今週（10/26（月）〜10/31（土）の6日分）の売上は 40,260円でした。
>
> 前週の同じ期間（10/19（月）〜10/24（土））の 28,850円と比べて、39.5%増えました。
>
> 店舗別では西店（15,250円）、カテゴリ別では文具（14,980円）の売上が最も多くなりました。

- **「今週」の決め方**：データの中でいちばん新しい日を含む週（月曜始まり）を今週とします。
- **前週とは同じ曜日までで比べる**：今週が途中まで（例：月〜土）しかないときは、前週も月〜土の売上で比べます。前週の7日分と比べると、実際より減ったように見えてしまうためです（上の例では、7日分と比べると約14%増、同じ6日分では約40%増と、印象が大きく変わります）。
- 前週のデータがない場合や、前週の売上が0円の場合は、その旨を文章で伝えます。

### 生成AI ではなく Python で文章を作った理由

最初は生成AI（Claude API）で文章を作る設計を検討しました。次の点を比べて、Python で決まった型の文章を作る方法を選びました。

| | 生成AI を使う場合 | Python で作る場合（採用） |
|---|---|---|
| 費用 | 1回ごとに利用料金がかかる（前払いが必要） | かからない |
| 文章の数字 | 生成AI が数字を書き間違える可能性があり、確認が必要 | 集計表と必ず一致する |
| テスト | 毎回同じ文章になるとは限らず、確かめにくい | 一字一句テストできる |

数字をまとめる処理（`summarize_latest_week`）と、文章にする処理（`make_comment`）を分けて作っています。将来、生成AI で表現を豊かにする場合も、数字は Python で計算したものを渡す形にして、数字の正確さを保てます。

2. 次のコマンドを実行します。

## 入力データの形式

1行目は見出しとして、次の7列が必要です（列の順番は自由で、ほかの列があっても問題ありません）。

| 日付 | 店舗名 | 商品名 | カテゴリ | 単価 | 数量 | 金額 |
|---|---|---|---|---|---|---|
| 2026-09-01 | 東店 | ノートA | 文具 | 200 | 5 | 1000 |

- CSV は **UTF-8**（BOM の有無はどちらでも可）で保存してください。Excel で保存するときは「CSV UTF-8（コンマ区切り）」を選びます。
- Excel ファイルは1枚目のシートを読み込みます。
- Excel でファイルを開いている間にできる一時ファイル（`~$` で始まる名前）は、自動で読み込みの対象外になります。

## サンプルデータについて

`input/` には、動作を試すための**架空の**売上データが入っています。

- 期間は 2026年5月〜10月の6か月、3店舗（東店・西店・南店）、18ファイル・1,112行です。
- 東店・西店は CSV、南店は Excel で保存しています（両方の形式を読み込めることを確かめるため）。
- 集計結果に意味のある違いが出るよう、次の傾向を入れています。
  - 土日は売上が多い（3店舗合計の1日あたりの平均：平日 約6,500円、土日 約9,600円）
  - 7〜8月は飲料がよく売れる
  - 店舗の規模に差がある（西店 ＞ 南店 ＞ 東店）
- 最初の週（4/27〜5/3）と最後の週（10/26〜11/1）は、データの期間の都合で途中の日までしかありません。そのため、週別の売上はほかの週より少なく見えます。

データは `tools/make_sample_data.py` で作っています。乱数の種を固定しているので、次のコマンドで何度作り直しても同じデータになります。

```powershell
.\.venv\Scripts\python.exe tools\make_sample_data.py
```

## エラーと警告

| 状況 | 動き |
|---|---|
| 入力フォルダがない／ファイルが1つもない | エラーメッセージを表示して終了 |
| 必要な列が足りない | どの列が足りないかを表示して終了 |
| CSV が UTF-8 ではない（Shift_JIS など） | 保存し直す方法を案内して終了 |
| 出力ファイルを Excel で開いたまま実行した | ファイルを閉じてから再実行するよう案内して終了 |
| 空欄・読み取れない値・マイナス値・金額 ≠ 単価×数量 | ファイル名と行番号つきで警告し、処理は続ける |

エラーで終了したときは終了コード `1` を、正常に終了したときは `0` を返します。

## テスト

```powershell
.\.venv\Scripts\python.exe -m pytest -v
```

pytest による自動テストが31件あります。

- ファイルの検索・読み込み・結合
- 店舗別・カテゴリ別・月別・週別の集計（週別は、日曜日が前の週に入ること・月をまたぐ週が1つにまとまることも確認）
- Excel の出力（シート構成・ファイル名・グラフ）
- エラー処理（フォルダなし・列不足・文字コード違い・ファイルなし）とデータチェック
- テスト専用の固定データ（`tests/data/`：2か月×3店舗・64行）の集計結果が、手で計算した値と一致するか
- 今週の売上の特徴（今週が途中までのとき前週も同じ曜日までで比べること、前週データなし・前週0円・変化なしの文章も確認）
- 画面の表示（Streamlit の AppTest で、集計結果・今週の特徴・警告・エラーの表示を確認）

テストは、テストの中で一時フォルダに作るデータと `tests/data/` の固定データを使います。`input/` のサンプルデータを入れ替えても結果は変わらず、`output/` にも影響しません。

## 処理の流れ

```
input/ のファイルを探す（find_input_files）
  ↓
1ファイルずつ読み込む（load_file）… 列の確認、日付・数値の形式をそろえる
  ↓
入力ミスをチェックする（check_data）
  ↓
1つの表に結合する（load_all）
  ↓
店舗別・カテゴリ別・月別・週別に集計する（summarize_by_*）
  ↓
Excel に出力する（write_report）
```

## 開発の進め方

AI コーディングアシスタントの [Claude Code](https://claude.com/claude-code) を活用し、次の方針で開発しました（詳しくは [CLAUDE.md](CLAUDE.md) に記載しています）。

- **小さな機能単位で進める**：「CSV を1つ読む → 複数を結合する → 店舗別に集計する → …」と1機能ずつ実装し、その都度コミットした。コミット履歴から、開発の流れを順に追えるようにしている
- **正解を先に決めて確認する**：テスト用の固定データの集計結果を先に手で計算し、ツールの出力と一致することを毎回確認した。最終的に、この確認を自動テストにした
- **架空のデータだけを使う**：実在する企業や個人の情報は使っていない
